# Администраторы и телепортация

Это инструмент управления новой альфой, а не восстановленная механика AWPlanet.

Роль хранится в `accounts[id].role` в приватном серверном сохранении. Только значение `admin` даёт доступ; отсутствующая роль и новые аккаунты получают `player`. Имя персонажа, регистрационный запрос и поля WebSocket-сообщения не назначают права. Поле `self.role` в снимке нужно только для отображения интерфейса.

Войдите администратором и откройте **M → Карта**. Блок «Телепортация администратора» позволяет ввести X/Z и нажать «Телепортироваться» либо включить «Выбрать точку на карте» и нажать на нужную клетку. В обычном режиме щелчок по карте задаёт маршрут.

Телепорт охватывает все 512 × 512 клеток исходного хранилища карты: `−256 ≤ X < 256`, `−256 ≤ Z < 256`. Щелчок выбирает центр клетки, включая крайние центры ±255,5. Разрешены отдельные области и непроходимые клетки. После переноса действуют обычные ограничения движения и боя; из заблокированной клетки можно выйти другим телепортом. Это не неуязвимость.

Сервер проверяет роль, подключение и конечность/границы координат. Успешный перенос отменяет выбранного противника и прежнее преследование этого игрока, сбрасывает отсчёт движения и отправляет всем сессиям самого аккаунта подтверждение с новым снимком. Клиент очищает маршрут и сразу переносит персонажа и камеру. Телепорт не меняет здоровье, тонус, деньги, опыт, вещи или содержимое банка. Уже начатая работа сохраняет зарезервированные материалы и обычное время завершения.

## Назначение существующему аккаунту

На выбранном VPS используйте скрипт из активного релиза. Он меняет только роль точного существующего аккаунта и делает приватную резервную копию. Аккаунты с похожим именем не создаются и не выбираются автоматически.

```sh
sudo systemctl stop aw-xedoc.service
cd /var/www/aw.xedoc.ru/current
sudo -u aw-game node node_modules/tsx/dist/cli.mjs scripts/set-account-role.ts \
  --state /var/lib/aw-xedoc/state.json \
  --name WizardJIOCb --role admin --service aw-xedoc.service
sudo systemctl start aw-xedoc.service
```

Перед изменением проверьте аккаунт и текущий релиз; после запуска проверьте health, роль в авторизованном снимке и карту в браузере. Не редактируйте сохранение работающего сервера: его следующий checkpoint может затереть изменения. Скрипт с `--service` отказывается работать, пока указанный сервис активен. Для снятия прав используйте `--role player` тем же способом.

Пароли, session cookies и полное приватное сохранение не нужны в отчётах и не должны попадать в Git. Назначение роли не даёт клиенту возможности изменять роли других аккаунтов.

## Проверки

`npm test` включает авторизацию, границы, сохранность экономики, завершение зарезервированного ремесла и блокировку одновременных записей. `node scripts/smoke-admin.mjs` проверяет HTTP/WS, две сессии, повторный вход и перезапуск с приватной фикстурой во временном каталоге ОС; production этот сценарий не затрагивает.

После развёртывания `node scripts/smoke-admin-public.mjs https://aw.xedoc.ru --expected-sha=FULL_SHA` проверяет на указанном релизе отказ обычному игроку с поддельной ролью. Он создаёт один обычный QA-аккаунт и выходит из всех выданных сессий. Проверка работающих кнопок, позиции и камеры выполняется отдельно в браузере. Отчёты без паролей/cookies находятся в игнорируемом `artifacts/admin-verification/`.
