# Исследование исходной карты AWPlanet

30 сентября 2026 года. Исследован публичный `webdata.data` как массив байтов, без запуска клиентского кода. Исходные модели, изображения и шрифты не экспортированы.

## Подтверждённая структура хранения

Пакет имеет сигнатуру `AWP\0`, версию 1, 305 записей каталога. Каждая запись: четыре little-endian u32 — тип, смещение, размер, распакованный размер. Начало данных: `16 + 305 × 16 = 4896` байт. В исследованном пакете размеры хранения и распакованные размеры совпадают.

Блок 304 имеет тип 5, длину **2 097 160 байт** и заголовок `4d415000ffffffff` (`MAP\0` и u32 `0xffffffff`). После восьми байт остаётся ровно **2 097 152 байта**.

Полезная нагрузка делится на **две последовательные плоскости по 262 144 little-endian u32**. Во второй плоскости нижние 16 бит дают ID объекта. `65535` обозначает отсутствие объекта. Все **13 085 непустых ячеек** ссылаются на именованные записи ранее извлечённого каталога: **214 различных ID**, неизвестных ID нет. Это сильная независимая проверка связи карты с каталогом.

Верхние 16 бит второй плоскости содержат дополнительное значение, названное `flagsRaw`. Его назначение пока не установлено. Оно может включать разные параметры; трактовать его целиком как поворот, высоту, этаж или скриптовый ID нельзя.

Первая плоскость имеет богатое распределение упакованных значений и пространственную связность. По структуре она похожа на параметры ландшафта/геометрии. Значения пока сохраняются как `planeARaw`, без присвоения им высоты или номера материала.

## Размер сетки: сильное свидетельство, ещё не официальный контракт

В заголовке нет явно записанных ширины и высоты. Для нескольких возможных ширин измерено совпадение младшего байта первой плоскости между ячейкой и ячейкой следующей строки:

| Кандидат ширины | Доля совпадающих соседних строк |
| --------------- | ------------------------------- |
| 128             | 0,1273                          |
| 256             | 0,0704                          |
| **512**         | **0,7247**                      |
| 1024            | 0,6208                          |
| 2048            | 0,5013                          |

Максимум при шаге **512**, уменьшение корреляции при его кратных и группировки предметов делают раскладку **512 × 512** очень вероятной. Однако один анализ байтов не доказывает направление осей, начало игровых координат и расположение поверхности/подземелья. Сетка также может содержать несколько областей, этажей и технических зон в общем адресном пространстве.

**Две плоскости массива нельзя называть «поверхность и подземелье».** Вторая плоскость содержит объекты, соответствующие ячейкам первой. Разделение уровней мира ещё предстоит определить.

## Новые сведения о таблице взаимодействий

В блоке типа 4 длиной 19 200 байт расположены 600 записей по 32 байта. Сопоставление с именами предметов даёт следующие подтверждённые связи:

- Запись 45: объект-цель 162 (печь), результат 165 (бронза), дополнительный объект 131 (оловянная руда).
- Запись 61: печь → железный слиток, дополнительный объект 168 (кокс).
- Запись 98: объект 169 (пресс) → 212 (бронзовый кинжал), дополнительный объект 165 (бронза).
- Записи 176 и 177: костёр/микроволновая печь → хлеб; альтернативный результат 336 — сгоревший хлеб.
- Запись 332: швейный станок → полотно, дополнительный объект 579 (нить).
- Запись 391: швейный станок → кевлар, дополнительный объект 616 (паутина).

Четвёртое и пятое u16 после первых трёх полей часто содержат дополнительные ID компонентов. Следующее u16 похоже на две отдельные u8-величины: например, 257 раскладывается в `(1, 1)`. В записи полотна значение 5, в записи кевлара 3. Это **кандидат количеств**, а не доказанное число расходуемых предметов: основной предмет может задаваться объектом, чья операция запускает взаимодействие, и правила его расходования ещё не установлены. Нельзя подменить рецепты новой игры этими числами до проверки полного контракта.

Объект «дискета: кинжалы» ID 222 содержит значение 98 в области метаданных, совпадающее с первым взаимодействием изготовления кинжала. Это полезная связь программы и набора операций. Остальные метаданные требуют отдельного разбора.

## Артефакт и повторение

`data/reference/map-layout.json` содержит исходные линейные размещения и упакованную первую плоскость, без оригинального арта. В нём явно указан статус `provisional`, кандидат ширины и неизвестный перевод в игровые координаты. Поле `flagsRaw` не используется для готовых утверждений о высотах/этажах.

```powershell
node scripts/inspect-map.mjs C:\путь\к\webdata.data --export
```

SHA-256 исследованного пакета: `9de0b9112f724166809ed91807333f806037721e45dba123e21056d15a63b848`.

Следующий шаг — сопоставить сетку с официальной картой и контролируемым просмотром оригинального клиента, затем установить кодирование ландшафта и перевести отдельные участки в новую геометрию. Текущая игровая сцена пока не заменяется этим исследовательским экспортом.
